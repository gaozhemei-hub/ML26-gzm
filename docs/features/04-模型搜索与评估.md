# 04｜模型搜索与评估

模型搜索阶段根据任务类型创建候选算法，使用训练集拟合，并依据验证集指标进行超参数搜索、比较和排序。模型选择的主指标可设置，也可使用任务对应的默认指标。

## 候选模型和调参

当前模型注册表提供随机森林、XGBoost、LightGBM 和 CatBoost。除随机森林外，使用其他算法需要在环境中安装对应可选依赖。通过 `ae.param.model_search` 可选择模型、设置 trial 数量和并行度、固定部分参数或覆盖搜索空间。

## 选模和测试评估

候选模型按验证集表现选择。最终模型在测试评估前锁定；候选排序不依据测试分数。测试指标和测试诊断用于描述锁定模型的最终结果，不应拿来反复选择候选模型。

Voting 组合（若在当前配置和运行中生成）用于验证集比较，不能替代锁定最佳单模型的测试结果。

## 结果

模型搜索结果位于 `ae.result.searched`，包括最佳模型信息、候选运行结果、验证指标和最终测试指标。模型搜索审计也会记录选模协议相关信息。详细参数和对象字段见 [API 参考：ModelSearchConfig 与 ModelSearchResult](../api_reference.md#34-modelsearchconfig)。

## 边界

- 实际可用模型取决于安装的可选算法库。
- 搜索预算和候选算法会影响运行时间与结果；不同工具或不同预算下的分数不能简单视为公平排名。
- 测试集只用于锁定后的评估，但之后的解释、诊断或重载核对可能读取测试输入；不应表述为测试数据在整个生命周期只读取一次。
