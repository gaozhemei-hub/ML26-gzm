# 06｜报告与证据交付

每次 `fit()` 会建立独立运行目录，保存总报告、阶段报告、图形资源、模型文件和结构化运行记录。可通过 `ae.output_dir` 和 `ae.result.report_paths` 获取实际目录和报告路径。

## 交付检查

证据交付模块根据任务和启用条件登记预期工件，并检查生成状态、文件位置和失败原因。常见状态包括：

- `generated`：工件已生成且通过文件存在性检查；
- `failed`：生成过程失败，并记录原因；
- `missing`：预期文件未生成或缺失；
- `not_enabled`：功能没有启用；
- `not_applicable`：当前任务或数据不适用。

通过 `ae.evidence_.audit()` 可读取交付检查结果。报告存在不代表所有工件均已交付；文件存在也不验证其科学内容正确。

## 局部补做

若某些已支持的工件生成失败或缺失，可在**原 Python 会话仍存活**时调用 `ae.retry_evidence()`，或指定可恢复的项目。局部补做复用拟合好的模型，不重新训练；数据、模型或相关配置发生变化时，应重新运行建模。

## 运行产物

运行目录一般包含 `report.html`、`reports/`、`evidence/`、`best_model.joblib` 和 `pipeline.joblib`；是否出现具体文件取决于任务、功能启用状态和生成结果。结构化交付清单通常保存为 `evidence/delivery.json`，审计记录和选模记录也保存在 `evidence/` 下。

详细状态字段、路径和恢复限制见 [API 参考：证据交付](../api_reference.md#6-证据交付与推断-evidence-delivery--inference)。
