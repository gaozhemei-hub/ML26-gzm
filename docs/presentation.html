四条原则 → 我们的起点

原则 1

注册表 + 能力声明

每个模型族在注册时声明自己需要哪些预处理：

模型需要 Scale需要类别编码
线性模型 / 神经网络✅ 是✅ 是
随机森林 / XGBoost❌ 否✅ 是
CatBoost❌ 否❌ 否（自带）

→ 框架根据模型能力自动匹配，不做一刀切

原则 2

Profile 只报事实，不做决策

第一步：DataInfo

只管「看」数据

  • 哪些列是数值 / 类别 / 文本 / 日期
  • 哪些有缺失值
  • 哪些偏态严重
  • 哪些需要标准化
→

第二步：PreprocessingTuner

再做决策

  • 预处理策略 = 数据事实 ∩ 模型能力
  • 两部分各自独立
  • Profile 只管描述，不管处理
原则 3

先划分，再预处理

  • 划分是实验设计
  • 预处理是数据变换
  • 统计量只能从训练集计算
  • 否则造成数据泄露
原则 4

产物自包含

  • data_info.json — 列信息
  • params.json — 运行参数
  • leaderboard.csv — 模型对比
  • 每个模型目录含 framework.json

一个目录 = 一次完整实验快照

这四条原则 → TabularX 继承并推进

TabularX 架构 · 2 min

纯函数分层

最核心的架构决策

纯函数层 core/

Profile · Split · Preprocess · ModelSearch · SHAP · Fairness

只做计算，零 IO，零副作用

▲ 通过 Schema dataclass 通信
编排+IO 层 estimator.py

串接各阶段 + 写 HTML + 存模型 + 保存图片

每个阶段测试只需「给输入、断言输出」，不用 mock 文件系统

Schema 契约

阶段间只通过 dataclass 通信

  • Profile → DataProfile
  • Split → SplitResult
  • Preprocess → PreprocessedData

契约不变，实现随便换

继承 MLJAR

注册表 + 能力声明

  • 按 binary / multiclass / regression 分桶
  • Profile 只做观测、不做决策
  • 参数集中管理 TabularXParams

功能 2

原生公平性审计

ae.fit(X, y, sensitive_features=["gender"])

一行代码，审计自动化

指标含义阈值
Demographic Parity各组正类率差异≤ 0.1
Equalized Odds TPR各组真正率差异≤ 0.1
Equalized Odds FPR各组假正率差异≤ 0.1

超阈值自动告警，零额外代码

功能 3

每个模型都有独立报告

MLJAR 主要对最优模型做详细解释。
TabularX 的做法：所有成功跑完的模型，都有自己的独立报告

  • 📋 评估指标（分类/回归）
  • 📊 混淆矩阵（分类任务）
  • 📈 ROC 曲线（二分类）
  • 📉 调参轨迹图
  • 🔄 对比优势一目了然

TabularX 不是要做一个「精度更高」的 AutoML

AutoML 在精度上已经很成熟了。

TabularX 要做的是——

让 AutoML 的每一次运行

都留下完整的、可追溯的、包含公平性审计的实验记录

数据怎么处理的？模型为什么选这个？对哪些群体可能有偏见？
